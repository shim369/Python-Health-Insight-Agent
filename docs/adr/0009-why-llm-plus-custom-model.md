# 0009: なぜGeminiと自作モデルを併用するのか

- 状態: 採用

## 背景
「今夜遅めに食べたら、明日の睡眠はどうなりそう?」のような**予測**の質問がある。選択肢は
(a) LLMに推測させる、(b) 通常の統計だけで答える、(c) 小さなモデルを作ってツールにする。

## 決定
予測の数値だけを**自作の軽量モデル**(LightGBM)が返し、Geminiは質問の解釈・ツール選択・説明を担当する(c)。

- (a) は、同じ質問で実行ごとに数値がぶれ、根拠も示せない。ADR 0001の「数値はLLMに考えさせない」に反する。
- (b) は過去の群間差・相関までは言えるが、「この食事時刻・就寝時刻なら」という条件つきの値は返せない。
- (c) はモデルの誤差(MAE)とBaseline比を**根拠として併記**でき、同じ入力なら同じ値を返す(一貫性)。
  一方で、モデルは「使ってよいとき」だけ使う必要がある(ADR 0010)。
- モデルは**最後に追加**した。Gemini+通常ツールだけで完結する版(Phase 8)を先に完成させ、モデルの有無を
  評価で比較できるようにした(`fake-all` と `fake-no-model`)。

## 結果
- 役割が明確になる: LLM=言葉、ツール=事実、モデル=条件つきの参考値。
- モデルの回答には必ず「参考値」「MAE」「Baseline比」を併記し、モデルを使っていないときはそう言わせる。
  (プロンプトの規則と、ツール結果の `reference_only` / `model_used` / `NO MODEL WAS USED` の注記で担保。)
- 保守対象が増える(特徴量・評価・採用判断)。小さく保つため、予測対象は睡眠時間の1つに絞った。
