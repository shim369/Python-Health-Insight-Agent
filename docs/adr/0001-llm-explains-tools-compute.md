# 0001: LLMは説明、数値と判定はツール

- 状態: 採用

## 背景
LLMは計算・統計・件数の数え上げで誤りやすく、もっともらしい数値を作ってしまう。健康ログでは
「ない関係を、あるように言う」ことが最も避けたい失敗になる。

## 決定
- Geminiは質問の解釈・ツール選択・結果の説明だけを担当する。
- 取得・集計・相関・比較・スコアは型付きツール(コード)が返し、**有意性の判定も計算済みの
  `interpretation` / `reliability` として返す**。プロンプトで「数値を再計算しない・結果を写す」と指示する。
- 件数が少ないとき(各群5件未満、相関10組未満)は結論を出さず `insufficient_data` を返す。
- 回答末尾の注意書きはLLMに任せず、コードが必ず付ける。

## 結果
- 数値のでっち上げを「回答中の数値がツール結果に根拠を持つ割合」で測れる(評価の `grounded`)。
- ツールが増えるほどプロンプトとツール定義の保守が要る。日付の対応(睡眠は起床日、要因は前日)も
  LLMに任せず、日次テーブルの指標名(`prev_day_*`)に固定した。
