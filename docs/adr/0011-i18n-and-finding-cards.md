# 0011: 多言語対応(日本語/英語)と、平易な所見カード

- 状態: 採用

## 背景
- 英語UIにしても、バックエンドが日本語固定の文(ヘルススコアの所見、モデルの採否理由、グラフのタイトル等)を
  返すため、日本語が混ざった。
- 統計ツールの結果が `prev_day_late_meal と sleep_duration_min: r=-0.754, 判定=strong_negative` のような
  内部名とコードのまま画面に出て、読み取りにくかった。睡眠時間も「分」では実感しにくい。

## 決定
1. **グラフの文言は {ja, en} の組で持たせ、APIが利用者の言語で解決する**(`tools/charts.py` の `tr()` /
   `localize()`)。ツールは言語を知らなくてよく、MCP経由でも両方が運ばれる。グラフはLLMに渡さないので、
   トークンも増えない。
2. **ツール結果の「文章」は、呼び出しごとの言語で作る。** 言語は引数(LLMに見せるスキーマ)ではなく
   `contextvars` で渡す(`ToolRegistry.execute(..., locale)` が設定し、ツールは `current_locale()` で読む)。
   MCPではリクエストの `_meta.locale` で運ぶ。対象はヘルススコアの所見・提案、モデルの採否理由、特徴量ラベル。
   スレッドをまたいでも呼び出しごとに独立し、終われば元に戻る。
3. **統計の結果は、コードが決定的に「所見」にする**(`services/findings.py`)。内部名ではなく指標ラベル
   (`label_ja`/`label_en`)を使い、強さ・向き・信頼度・平易な1文を作る。UIはこれを**グラフの直下の所見カード**
   (強さのメーター・件数・信頼度、比較は表)として出す。キー無しのデモLLMの文面も同じ表現を使う。
   LLMの文章ではないので、数値と判定がぶれない(ADR 0001の延長)。
4. **表示の単位だけを変える。** 睡眠時間は分で保存・計算し、画面では時間(7.5)で見せる。0/1の指標の平均は
   「該当した日の割合(%)」で見せる。LLMに渡すツール結果は分のまま(根拠の数値を変えない)。
5. 利用者自身のデータ(振り返りメモ、種目名)は翻訳しない。チャット中の過去の回答も、質問した時の言語のまま残す。
   本物のLLMの回答言語は、システムプロンプトの「Answer in …」で決まる。

## 結果
- 英語で質問したときの回答・グラフ・所見カード・提案・モデル理由に日本語が混ざらないことを、テストで固定した
  (ヘルススコア・モデル・MCP往復・API)。
- 文言を足すたびに日英の両方が要る(`tr()` / `_t()`)。モデル理由は保存ファイルの後方互換のため `reason_en` を任意項目にした。
- 評価の質問セットとADR・要件定義は日本語のまま(README に明記)。
