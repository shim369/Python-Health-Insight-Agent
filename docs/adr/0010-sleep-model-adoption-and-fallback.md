# 0010: 睡眠モデルの採用基準とフォールバック

- 状態: 採用

## 背景
小さなデータ(数十〜百日)では、モデルが「良さそうに見える」だけで実は過学習していたり、単純な平均と
大差なかったりする。使うべきでないときに使うと、もっともらしい誤った予測を出してしまう。

## 決定
既存アプリの採用判断(ml/evaluation.py)と同じ基準を、睡眠(新規領域)に**独立して**適用する。

1. **前提チェック(評価の前)**: ログ60日以上、欠損率30%未満、使えるサンプル30件以上。満たさなければ
   評価せず見送り、通常の統計にフォールバックする。
2. **評価**: forward-chaining の時系列5分割。ランダム分割はしない(未来のリーク防止)。
3. **採用条件(両方)**: (a) Baseline(直近7夜平均と学習平均の**良い方**)比で検証MAEが相対10%以上改善、
   (b) (val−train)/val が20%以内。(b)を超えたら(a)を満たしても**不採用**。
4. **フォールバック**: 不採用・データ不足・学習/推論の例外のいずれでも、`model_used=false` と理由、
   通常の統計(直近平均、遅い食事の夜とそれ以外の平均、特徴量と睡眠の相関)を返す。黙って落とさない。
5. **運動なしの日は欠損にしない**(0として扱う)。既存アプリで、運動時間Noneを他の欠損と同じに扱い、
   常にフォールバックになる不具合があったため。回帰テストで固定。
6. 採用判断と根拠はJSON(ユーザーごと)に、学習条件・指標はMLflow(ローカルSQLite)に保存する。
   MLflowのfileストアはメンテナンスモードで例外になるため、SQLiteを使う。記録の失敗で回答は止めない。
7. 学習済みモデル自体は保存せず、データが変わったときに再学習する(数十件で一瞬・乱数は固定)。

## 結果
- 合成データでは、正則化した設定が Baseline比31.6%改善・乖離-16%で採用される。過学習しやすい設定は
  乖離60%で不採用になる(テスト)。これはパイプラインの動作実証であり、予測精度の成果としては扱わない。
- 実データでは採用されない可能性が十分あり、その場合も回答は統計で成立する。
