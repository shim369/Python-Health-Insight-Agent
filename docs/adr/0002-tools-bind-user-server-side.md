# 0002: ツールは`user_id`をLLMから受け取らない

- 状態: 採用

## 背景
LLMの出力は信頼できない入力(プロンプトインジェクションの可能性がある)。他ユーザーのデータを
取得できる引数があると、分離がLLMの良心に依存してしまう。

## 決定
- ツールの引数スキーマに `user_id` を持たせない。`ToolRegistry.execute(user_id, ...)` が認証済みの
  コンテキストから注入する。引数モデルは `extra="forbid"` なので、LLMが渡しても拒否される。
- Repositoryの全メソッドが `user_id` を必須引数にし、全SELECTに条件を付ける(分離テストあり)。
- MCPサーバーも起動時に1ユーザーへ束縛し、クライアントは別ユーザーでの呼び出しを送らず拒否する。
- LLMには `user_id` もメールアドレスも送らない(データ最小化。テストで検査)。

## 結果
- 分離の強さがツール・Repositoryの実装だけで決まり、LLMの挙動に依存しない。
- 認証方式(OAuth等)を後から入れても、差し替え箇所は `current_user_id` だけで済む。
