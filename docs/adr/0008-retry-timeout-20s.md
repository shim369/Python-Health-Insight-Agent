# 0008: Geminiのタイムアウトは20秒(既存は60秒)

- 状態: 採用

## 背景
既存アプリのRetryPolicyは最大3回(初回+リトライ2回)・1秒×2倍のバックオフ・ジッター±20%・
429/503のみ・**1回60秒**。本プロジェクトの指定は「既存と同じ値、1回20秒」で、1項目だけ食い違う。

## 決定
- 他の値は既存と同じにし、1回あたりのタイムアウトだけ **20秒**にする。
- 理由: エージェントは1質問で複数回(ツール呼び出しごとに)LLMを呼ぶ。1回60秒だと最悪ケースが
  数分になり、チャットUIとして破綻する。
- リトライは429/503のみ。タイムアウト・検証エラーは再試行しない(無条件には再試行しない)。
- 生成と埋め込みで同じ `call_with_retry` を使う。

## 結果
- 最悪ケースの待ち時間は1回あたり 3×20秒 + 約3秒。長い応答が必要になったら `RetryPolicy` を変えて調整する。
- 実キーで確認した注意: Geminiの無料枠は1分5リクエスト程度で、1質問に3〜5回かかるため429になりやすい。サーバーは `retryDelay`(例: 45秒)を返すが、
  本方針(1秒×2倍・最大3回)では待ち切れない。無理に長く待たず、利用者には「利用上限に達した。1分ほど待って」と具体的に伝える。
  評価では `--pause` で質問の間隔をあける。
